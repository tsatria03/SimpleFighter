Builder templates.

A builder template is a ready made object you can drop into a map in one action instead of laying down every piece by hand. A couch, a table, a bed, a small structure: rather than placing each wall and platform yourself, you build the object once, save it as a template, and from then on you place the whole thing at a spot of your choosing. Templates are made entirely of ground and walls, so they are shapes you walk on and bump into, not sounds or behaviors. Everything else about the spot, such as what it is called or how it feels underfoot, stays yours to add afterward.

Placing a template.

Open the builder menu and look at the bottom of any category tab. A template entry sits there on every tab, no matter which category you are focused on, so it is always one step away. Choosing it opens a form that asks where to put the object and which object to put. You get an x and a y, plus a z on 3d maps, and these fill in from your camera markers if you have set them, so you can mark a spot with your camera and let the form carry the numbers over. Then you choose a path, a category, and finally the template itself. Press okay and the object appears at the spot you gave, at the size it was built, with the whole thing placed at once.

The spot you give is a single corner, not a box. The template keeps the exact size it was authored at; your coordinates only decide where it lands. Placing the same template at a different spot simply moves the whole object there unchanged.

The path: global, map, or any.

Every template lives in one of two places. Global templates sit in a shared library that every map can reach, so a couch you save globally is available on any map you build. Map templates live inside one particular map and travel with it. The path in the placement form chooses where to look. Global looks only in the shared library. Map looks only in the current map's own templates. Any looks in the map first and then the shared library, so a map's own version of an object quietly wins over a shared one of the same name, and if the map has none it falls back to the shared copy.

Categories.

Templates are grouped into categories such as bedroom or kitchen, and every template belongs to one. A category is simply a named group; you create one by making it, and once it exists the forms list it for you to choose from. Categories keep a growing collection tidy and are how you find the object you want when placing.

Moving or removing a placed template.

Because a placed template is a single reference to the object rather than a pile of loose pieces, moving it is easy. Find its line in the line editor and change the coordinates, and the whole object jumps to the new spot. Remove that one line and the whole object is gone. You never have to hunt down and edit each wall and platform individually, which is the main comfort of placing objects this way.

Managing your templates.

Everything to do with building and maintaining templates lives in the data manager menu, under builder templates. There you will find add, edit, remove, and view. Add creates a new template. Edit changes an existing one. Remove deletes one after asking you to confirm. View shows you a template's contents and description without changing anything.

Adding a template.

Adding a template is like copying a piece of a map into a reusable object. You give the new template a name, a short description, and the mode it is built for, and you choose whether to save it to the shared library or to a map. The heart of the form is a large text area where the object's ground and walls go. You can type them in by hand, or paste a chunk of a map you copied elsewhere and trim it down to just the object you want. Paste as much as you like; nothing is checked while you work.

The check happens when you save. If every line is a valid piece of ground or wall for the chosen mode, the template is written and you are told it was saved. If any line is something else, such as leftover map settings, an element that is not ground or a wall, or simply a malformed line, you are told how many lines are wrong and where the first one is, and nothing is saved until you fix it. This keeps every template clean and made only of the pieces a template is allowed to contain.

What a template can contain.

A template is made of ordinary ground and walls only: plain platforms, staircases, and walls. It cannot contain moving or vanishing platforms, and it cannot contain zones, enemies, items, or any other element. This is on purpose. A template is the shape of an object, and anything that gives a spot a name, a sound of its own, or a behavior is left for you to add in the map after you place the template. So if you want your couch to announce itself, place a text zone over it once it is down; if you want a hazard beside it, build the hazard as usual.

Fixed size.

A template is placed at the exact size it was built. There is no stretching a small couch into a large one as you place it, because a hand built object has no way to know which parts should grow and which should stay. If you want a bigger version, save it as its own template, such as a large couch alongside the small one. This keeps every object looking and sounding exactly as it was made, wherever it lands.

Global versus map templates, and compiling.

The choice between a global template and a map template matters most when you share a map. When you compile a map, any object placed from the shared library is written permanently into the map as ordinary ground and walls, so the finished map carries a full copy and needs nothing from your library to work. An object placed from the map's own templates is different: because that template travels inside the compiled map, the object stays a light reference and the template rides along with it. Either way the person you share with sees your furniture exactly as you placed it. The difference shows only if that person opens the map to edit it, where a shared object arrives as plain pieces and a map object arrives still tied to its template.

If a template a map refers to has gone missing, the object it would have placed simply does not appear. There is no error; the spot is just empty, which you will notice as you walk the map.

Editing and viewing.

Editing a template opens the same large text area holding the object's current ground and walls, along with its description, ready for you to change. Saving runs the same check as adding, so an edit can never leave a template in a broken state. Any object already placed from that template picks up the change the next time the map loads. Viewing shows the same contents and description read only, for when you just want to look.

Creating a template by hand.

You do not have to use the add form; a template is just two small files in a folder, and you can make one with any text editor if you prefer. Templates live in a shared library at data/builder/templates, and a map's own templates live inside the map's folder at templates/builder. In either place the layout is the same: a folder named for the category, a folder named for the template inside it, and the two files inside that. So a bedroom couch in the shared library is the folder data/builder/templates/bedroom/couch, and the same couch belonging to a map is templates/builder/bedroom/couch inside that map's folder. If the category folder does not exist yet, make it, and that alone is all it takes to create a category.

Inside the template's folder go two files. The first is main.sif, which holds the object itself. Its first line names the mode the template is built for, written as the word mode followed by 2d, topdown, or 3d, and this should match the maps you intend to place it on. Every line after that is one piece of ground or wall, written exactly as it appears in a map, and only platforms, staircases, and walls are allowed. The coordinates you use are the template's own; they are shifted to wherever you place the object later, so build it around any convenient spot. The second file is meta.sif, and it holds a single line beginning with description= followed by a short sentence about the object. That sentence is what you hear when you look the template up in the menus.

As an example, the main.sif for a small couch might begin with the line mode 2d, then carry its ground and walls one per line, such as wall 5 5 0 4 1 wallcloth 0 100 none false false, then platform 5 5 4 1 carpet5 0 100 false false, and so on. Its meta.sif would be the single line description=A comfortable looking couch. With those two files in place under a category folder, the couch appears in the menus like any other template, ready to place.

Authoring a template line by hand.

If you edit a map's main file directly, an object placed from a template is a single line: tpl, then the x and y (and a z on 3d maps), then the path, the category, and the template's name. For example, tpl 5 2 any bedroom couch places the couch from the bedroom category at 5, 2, looking in the map first and then the shared library. The coordinates are where the object's corner lands; its shape follows from there, so you can move an object just by changing those two or three numbers.
