Map variables.

A map variable is a named number you define once and reuse by name anywhere else in the map. You give it a name and a value, and from then on writing the name with a dollar sign in front of it, like $spot, is replaced with that value wherever it appears. A map variable has no position of its own; it is not placed anywhere in the world, it simply holds a number for the rest of the map to borrow.

Defining a variable.

You build a map variable from the misc section of the build menu, or by typing it into the build command. It asks for two things: a name and a value. The name must start with a letter and can contain only letters, digits, and underscores, so home_x and gate2 are fine but 2fast and my name are not. The value is a plain number, or a random range written as random(low,high). That is all a variable is: a name and a number.

Using a variable.

Anywhere you would write a number in the map, you can instead write the variable's name with a dollar sign in front, and it is filled in with the value when the map loads. If you have a variable named spot set to thirty, then $spot means thirty. The name is read up to the first space or punctuation, so both $spot on its own and $spot in $spot, end cleanly at the variable. This lets one variable fill in a coordinate on many different objects at once.

Define before you use.

The map is read from top to bottom, so a variable only works on the lines that come after it is defined. Build the variable first, then build the things that use it. Because building always adds to the end of the map, this happens naturally: make the variable, then make the sign, door, or sound that references it, and they will sit below it. If you reference a variable that has not been defined above the line, it is left as plain text and the map errors box warns you that the variable is not defined, so a typo in a name is easy to spot.

Sharing one random value.

The most useful thing a variable does is freeze a random number so several objects can share the same one. Writing random(5,40) directly in two different places rolls a new number each time, so the two never match. Put the random range in a variable instead, and it is rolled once when the map loads and held; every use of that variable then reads the same rolled number. So a variable named dest set to random(5,40), used as the coordinate of a sign, a travelpoint, and a sound source, links all three to one random spot that changes each time the map is loaded but stays the same across that whole load.

Naming a coordinate once.

A variable is also handy for a position you might move later. If an object spans several lines, or several objects share a location, putting that coordinate in a variable means you change it in one place instead of hunting down every line. Set home_x and home_y once, use $home_x and $home_y everywhere the spot is needed, and moving the whole thing later is a single edit.

Authoring a map variable by hand.

If you edit main.sif directly, a map variable line is written as: mapvar name value. For example, mapvar spot 30 defines spot as thirty, and mapvar dest random(5,40) defines dest as one frozen roll between five and forty. The line can sit anywhere in the file as long as it comes above the lines that use its name. A value is rolled fresh each time the map loads, so a random variable gives a new number on every load while staying the same everywhere within that load.
