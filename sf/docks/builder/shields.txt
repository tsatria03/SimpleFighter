Shields.

A shield is a defensive equipment item that absorbs damage on the player's behalf. When a shield is up, incoming bullet, projectile, melee swing, mine, bomb, time bomb, and contact damage hits the shield's strength pool instead of the player's health, with the shield's defence value subtracted from the raw damage first. The shield breaks when its strength reaches zero, leaving the player with no shield equipped until they draw another one.

Each shield lives in its own folder under sounds/decompiled/main/equipments/shields/. The default shield is none, which means the player has no shield drawn and incoming damage goes straight to health.

Sound assets and info.sif files.

Shield data lives in info.sif files under sounds/decompiled/main/. The full path is sounds/decompiled/main/equipments/shields/<shield>/data/info.sif.

The paths shown below describe the decompiled (loose folder) form of these files. The game also accepts the compiled pack form of the same content (the global main.spack at sounds/compiled/main.spack), and the lookup order is folders first, packs as fallback, so the two forms can coexist on disk. See the packs help topic for the full explanation of how decompiled folders and compiled packs interact.

Each shield has its own info.sif. The file is self contained: every stat the shield uses is written explicitly, and anything left out falls through to a sensible default.

The info.sif file does not list any sounds. The engine learns what audio a shield has by scanning the shield's general/ subfolder, matching whatever clips it finds against the names it expects (draw, wear, hit, loop, remove, break). Drop a clip in general/ and the shield plays it; remove it and the shield goes silent for that event. There is nothing to wire up by hand because the folder layout is the audio configuration.

Field reference.

Every field in info.sif uses the form key=value, one per line. Missing fields fall back to the defaults shown below.

defence (double): How much damage the shield absorbs per hit before passing the rest to the strength pool. The actual reduction is defence times three, so a defence of ten removes thirty raw damage from each incoming hit. Defaults to 0.

wear mode (int): How the shield is worn. 0 is body armor mode: pressing O puts the shield on, pressing O again takes it off, and while the shield is on the player can still move, fire, and jump as normal so the shield acts as passive protection. 1 is brace mode: holding O keeps the shield up, but while it is up the player cannot move, fire, or jump, and releasing O drops the shield and restores all three actions. Brace mode trades mobility for an active commitment to defense, body armor mode lets the player keep playing the game while protected.

weight (int): How much the shield slows the player down while drawn. Heavier shields cost movement and reaction speed. Defaults to 1.

shield strength (double): The shield's starting and maximum strength pool. The shield starts at full strength when drawn, and when this hits zero, the shield breaks and the player returns to no shield. Defaults to 100.
shield passthrough (bool): Whether the attacker's own audio plays alongside the shield's hit clip on a catch, so you can hear what's hitting you through the block. With shield passthrough=true, an armed npc or tts enemy still fires audibly into a raised shield, and a projectile, bomb, time bomb, mine, spike, or force field plays its normal impact alongside the shield clang. With shield passthrough=false, only the shield clang plays — useful for a shield meant to fully muffle incoming sound. Bullet impacts play the clang only either way, since the npc's fire sound already played when the bullet left, so adding the bullet's impact clip would just be redundant. Defaults to true.

unlock level (double): The minimum character level required to draw this shield from the shields menu. Locked shields appear in the menu with an (Unlocked at level X) suffix and cannot be selected until the player levels up enough. Defaults to 1.

blockchance (int or int:bool pair): The percent chance the shield catches a hit, with an optional cushion sub-value controlling how much absorbed damage chips the strength. Written as blockchance=N for a plain chance with no cushion, blockchance=N:true to cushion it (a catch halves the damage chipped from the strength pool before defence is subtracted, like padded armor or a softening field), or blockchance=N:false (or omitted) for no cushion, so the catch takes full damage minus defence. Clamped to 0-100 on read. Defaults to 100, cushion off, so a stock shield catches at full damage; the default shields ship with blockchance=80, so roughly 1 in 5 hits slips past to your health, feeling more like body armor with occasional gaps.

launch type (string): What the shield fires back when it absorbs an enemy hit. launch type=projectile:<name> fires that projectile from builder/kombat/projectiles/<name>; launch type=bomb:<name> drops that bomb from builder/traps/bombs/<name>. launch type=none (or omitted) disables the counter — the default shields ship with launch type=none as a visible starting point; change it to a projectile or bomb to turn it on. The counter travels toward the attacker (the cardinal direction from you to them, up or down on 3d), inherits the absorbed damage, and fires only on enemy attacks: npc melee, npc bullets, and tts enemies. Trap damage — spikes, mines, force fields, time bombs, bombs — never fires it, even when absorbed.

x launch range (int): How far in tiles the counter-attack's projectile or bomb-drop travels along the x axis. Defaults to 0, and the default shields all ship with the explicit x launch range=0 alongside the other launch fields.
y launch range (int): How far in tiles the counter-attack travels along the y axis. Defaults to 0.
z launch range (int): How far in tiles the counter-attack travels along the z axis (height). Defaults to 0. Only consulted on 3d maps; on 2d and topdown maps the field is ignored. Setting all three ranges higher than zero gives the counter-attack a real reach; leaving them at zero with a launch type configured produces a same-tile counter-attack that lands at your feet.

The three launch range fields also accept the literal bounds keywords minx, maxx, miny, maxy, minz, and maxz in place of a number. When the parser sees one of those keywords it substitutes the active map's full span on that axis at parse time — so x launch range=maxx on a 100-tile-wide map resolves to 100, on a 500-tile-wide map resolves to 500, and so on. This lets a counter-attack reach across the entire map regardless of size, instead of hardcoding a tile count that's wrong for half your maps. Any non-keyword value still parses as a plain integer the way it always has.

launch speed (int): How fast the counter-attack's projectile moves through the air, written as milliseconds per tile of travel. Lower values mean a faster projectile. Defaults to 30, which the default shields all ship with explicitly. For a bomb launch, this doubles as the bomb's per-tick fall interval, so a slower launch speed also produces a slower-falling counter-bomb.

Shield manager.

The shield data tools live in the main menu's miscellaneous → data manager menu → shield entry. Opening it brings up a four button chooser that covers every authoring action: add, edit, remove, and view.
The same form reopens after each action so you can chain operations without bouncing back to the menu.

Add. Picks a shield from a list of every folder under sounds/decompiled/main/equipments/shields/, then opens a flat form with every info.sif field as its own input box.
Every field is required on save, with no defaults, so the saved file always has a complete entry for every key.

If an info.sif already exists for the chosen shield the form prompts to overwrite before writing.

Edit. Same one-list selection as Add, but the list filters to only show shields that already have an info.sif.
Selecting one opens the same flat form prefilled with the existing values.

Saving silently overwrites the file with no prompt because editing always intends to replace what's there.

Remove. Same shield list as Edit but rendered as a multi select.
Toggling shields with space adds them to the deletion set, and pressing remove brings up a confirmation prompt with the count of files about to be deleted.

Only the info.sif files are removed; the audio folders themselves are left untouched.

View. Same shield list as Edit, plus a read only multiline contents box that shows the raw info.sif text for the focused shield.
Arrowing through the list updates the contents box in real time so you can scan multiple files without reopening the form.
