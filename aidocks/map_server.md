Plan + running record for the **map server** — letting players fetch compiled maps from the dev's VPS from inside the game AND upload their own for the dev to moderate. **Both halves are built and proven working (2026-08-29).** The download side came first (a static server can *serve* but can't *receive*); the upload side then replaced the static server with a stdlib Python server that both serves downloads and accepts moderated uploads, plus a local `sf_map_approver.py` the dev runs to approve/reject the queue. Historically built one section at a time, confirming each before coding ([[feedback_confirm_before_implementing]]), committing between. **NOTE: the "Server side — Caddy" and "Phase 1 / Sections to build" material below is HISTORICAL** — Caddy was replaced by `sf_map_server.py`; read the "Phase 2 — upload" section for the current server/approver architecture.

## Why the VPS (not GitHub)
A compiled map is a single self-contained `.map` pack — custom sounds, map-scoped builder templates, baked geometry all travel inside the one file (see [[project_build_pipeline]]). Downloading is just "fetch one file, drop it in the compiled folder, it plays." The dev prefers the VPS over GitHub because asset-heavy packs can exceed GitHub's per-file/repo/bandwidth limits; a VPS folder has none.

## Index format — enriched, generated IN-GAME (evolved 2026-08-29)
Each line is **`name|mode|bytes`** (pipe-delimited), e.g. `old_house|2d|3985` — the map name WITHOUT the `.map` extension (dev-requested 2026-08-29; the generator strips it via `string_replace(fn, ".map", "", true)`, decompile_map's pattern), the mode (2d/topdown/3d), the raw byte size. The download menu splits on `|` and shows **"old_house, 2d map, total size, 3.89KB"** (size via `measure_file_size`, mode from the middle field) — matching the compile/decompile menus' look. **The download re-appends `.map`** when building the URL/local path (`fileword`), tolerating a name that still carries `.map` (so an older index or hand-written line with the extension still works). **Graceful fallback:** a line with no `|` shows just the name, so the menu never breaks on a stale/hand-written index. Note the success dialog uses the re-appended form ("old_house.map has been downloaded…").
- **Generated in-game** by `generate_compiled_map_index()` (`packfuncts.nvgt`, next to compile_map/decompile_map), reached from the **map tools menu** (`maptoolsmenu()`, `menu.nvgt`) as **"generate compiled map index"** (id `gcmi`, placed after "decompile map"). It scans `data/builder/maps/compiled/*.map`, reads each map's mode (`read_map_mode_compiled`) and size (`file_get_size`), and writes **`data/builder/maps/index.txt`** (the maps folder, one level ABOVE the compiled/ packs — kept out of the compiled folder so it isn't mistaken for pack content; success alert "Indexed N maps to maps/index.txt"). If `index.txt` already exists it asks yes/no before overwriting first (lowercase menu, "The index file already exists. Do you want to overwrite it?" — matching compile_map/decompile_map; no → speaks "canceled" and returns). The dev uploads that `index.txt` to the server ROOT, and the `.map` packs to the server's `maps\public\` subfolder.
- **Why in-game, not a server batch:** the mode lives INSIDE the compiled pack; a server-side `dir /b` batch can't read it. So index generation moved into the game (which can open packs). **`index_gen.bat` is RETIRED** — deleted from the repo (`sf/`) and the dev removed the VPS copy. (History: the original plan was a plain filename-only auto-index via that batch — "Shape A" — superseded 2026-08-29 when the dev asked to show mode + size, which the batch can't produce.)
- **Host workflow now:** compile maps → run "generate compiled map index" in-game → upload the `.map` files (to `maps\`) + `index.txt` (to root). Regenerate + re-upload whenever the map set changes.
- Current maps (all underscores, no spaces): 2d_test, 3d_test, elevator_example, old_house, old_main, topdown_test.

(The base-URL global was originally added to `updater.nvgt`; the dev moved the whole block out into the two dedicated files.)

**Menu:** in `mapmenu()` (`map_menu.nvgt`, the OUTER maps menu — items: load map / new map / back), add **"download map"** right AFTER "new map" (dev-chosen slot): `m.add_item("download map", "dlmap");` + handler `if(buildem=="dlmap") { download_map(); continue; }`.

**Function `download_map()`** — lives in **`updater.nvgt`** (home of `downloadsounds()`, the analogous download FLOW; NOT downloaderfuncts.nvgt, which is helpers like `beep_percentage`; `dl_file` itself is in `downloader.nvgt`). A one-line base-URL global sits at the top of `updater.nvgt` so the domain lives in ONE place: `string map_server_url = "http://reality-breaker-studios.net";`. Flow:
1. `url_get(map_server_url + "/index.txt")` → on "" or an HTML error page (`string_contains(.,"<!DOCTYPE",1) > -1`, the updater's own guard) alert + bail.
2. Parse with `clean_lines_from_text()` (extrafuncts — trims, drops blanks) → for each line, `string_split(line, "|", true)`: field 0 = filename (menu id + URL), and if ≥3 fields the display is `filename + ", " + mode + " map, total size, " + measure_file_size(parse_int(bytes))`; else just the filename (plain-index fallback).
3. On pick: if `file_exists("data/builder/maps/compiled/"+name)`, confirm overwrite BEFORE replacing — never silent (dev-agreed). Uses a **menu** (`m.add_item("yes")`/`m.add_item("no")` — LOWERCASE, yes first, `intro_text = "This map already exists. Do you want to overwrite it?"`), NOT the visual `question()` dialog (dev-requested 2026-08-29). Both the wording and the lowercase labels deliberately match `compile_map`'s own overwrite menu — the dev explicitly chose lowercase here to match that sibling tool, overriding the capitalized-label default in [[feedback_yes_no_menu_labels]] for local consistency. `conf = m.run()`; anything but index 0 (no, or escape's -1) speaks "canceled" and `continue`s back to the list. Then `dl_file(map_server_url + "/maps/" + name, "data/builder/maps/compiled/" + name)` (the existing progress-beep downloader; returns "finished"/"canceled").
4. **Validate before declaring success** (dev-requested 2026-08-29): a map listed in the index but MISSING on the server still "downloads" — `dl_file` doesn't check HTTP status, so Caddy's 404 page lands in the file as junk. So after "finished", check `read_map_mode_compiled(local) == ""` (the pack won't open / has no mode) → `file_delete(local)` + alert "That map isn't available on the server right now." + `continue`. Otherwise → success alert "Download complete" / "<name>.map has been downloaded. You can now play it from the compiled maps menu." (Note: `dl_file` already overwrote any prior copy at `local` before this check, so the delete only removes junk, no good copy is lost that wasn't already gone.)

The whole pick→download is wrapped in a **`while(true)` loop** (modeled on `compile_map`/`decompile_map` in `packfuncts.nvgt`, dev-requested 2026-08-29): the index is fetched ONCE up front, then the menu re-presents after each download so the player can grab several maps in a row. Escape or the "back" item is the only exit (speaks "canceled"); overwrite-decline and download-failure `continue` back to the list rather than returning. Function is `void`, so the while(true)-with-returns has no "not all paths return" issue ([[project_angelscript_while_true_return]] applies only to value-returning funcs).

**Playback needs NO wiring:** compiled maps are listed by `find_files("data/builder/maps/compiled/*.map")` (`map_menu.nvgt` ~:670), so a downloaded pack auto-appears in load map → compiled maps and plays via `load_map(name, owner, force_compiled:true, force_spawned:true)`. Local compiled path is `data/builder/maps/compiled/<name>.map` (cwd `sf/`, see `packfuncts.nvgt:18`).

**Decisions locked:** overwrite asks Yes/No first (dev-agreed); every escape/back speaks "canceled" ([[feedback_menus_say_canceled]], [[feedback_yes_no_menu_labels]]); map filenames must avoid spaces (all current ones do — else `dl_file`'s raw URL breaks; URL-encoding deferred). Plain `http` for now (works with `url_get`/`dl_file`); HTTPS is a later one-flag Caddy change, mostly relevant once uploads carry a token.

So the review queue mirrors public: `maps\pending\<name>.map` files PLUS `maps\pending_index.txt`. Re-uploading the same name replaces its line. The public `public_index.txt` is never touched by an upload → moderated. (This resolves the OPEN PLANNING mode question below for the upload path: the mode is captured at upload and carried in the pending index; approval just moves the file + the line.)

**64-bit size fix (2026-08):** the download menu's size display now uses `int64(string_to_number(...))` instead of `parse_int(...)` — `parse_int` is 32-bit and overflows right at 2 GB, so a ~2 GB map would have shown a garbage size.

**ENGINE FINDINGS — native HTTP upload IS possible; SUPERSEDES the earlier "bundle curl.exe" plan (surveyed 2026-08 from `misc/Legacy-NVGT/src/internet.cpp` + `datastreams.cpp`).** NVGT (this legacy fork) wraps Poco networking richly:
- **`http_client`** / **`https_client`** (the ACTUAL registered names — `internet.cpp:809-810` register `HTTPClientSession` as `"http_client"`, NOT `http_client_session`; getting this wrong = "Identifier 'http_client_session' is not a data type", the first compile error 2026-08) — factory `(const string&in host, uint16 port=80/443)`; `datastream@ send_request(http_request&)` returns the **writable request-body stream**; `datastream@ receive_response(http_response&)` returns the response body; plus `abort()`, timeouts. (`http_request`/`http_response` names ARE correct as-is.)
- `http_request(const string&in method, const string&in uri, const string&in version=HTTP_1_1)`; settable `method`, `uri`, `content_length` (int64), `content_type`. `http_response` has `http_status get_status()`. Method constants `HTTP_POST`/`HTTP_PUT`/`HTTP_GET`/… are globals.
- **`datastream.write(const string&in) → uint`** (bytes written) is script-exposed (`datastreams.cpp:330`) — the load-bearing call: lets us push the `.map` body in chunks.
- Also present but NOT used here: `url_post(url, data)` (synchronous, whole body as one string — would load 2 GB into RAM + no progress), `url_get`, `url_request`, and an FTP client with `begin_upload`.
- The async `internet_request` object (what `dl_file` uses for download progress) is download-to-file only — no upload analog. So upload uses the low-level session API instead.

So the plan is a **native `ul_file(url, disk_file, …)`, the upload twin of `dl_file`** (no curl, no external process, no bundling): open the local file + get size; `http_client_session sess(host, port)`; `http_request req(HTTP_POST, path_with_query); req.content_length = size`; `datastream@ body = sess.send_request(req)`; **loop** reading 64 KB chunks and `body.write(chunk)`, tracking sent bytes — and BETWEEN chunks handle the exact `dl_file` keys (**1**=size, **2**=uploaded, **3**=remaining, **space**=percent, **h**=help, **m**=mute beeps, **escape**=cancel→`sess.abort()`) + `beep_percentage`; then `sess.receive_response(resp)` and branch on `resp.status` (200→finished, 403→bad token, 413→too large, else failed) to relay the server's reply. Chunked script-driven loop = live progress, mirroring the downloader piece-for-piece (dev-requested UX).

**BUILT 2026-08 (client upload, needs dev compile-check — uses HTTP-client APIs new to SF):**
- **`ul_file(url, disk_file, …)`** in `updater.nvgt` — the `dl_file` twin, native Poco (no curl). Parses host/port/path from the url; `http_client_session@ session = http_client_session(host, port)`; `http_request@ req = http_request(HTTP_POST, path)`; `req.content_length = total`; `datastream@ body = session.send_request(req)`; loops `f.read(65536)` → `body.write(chunk)`, tracking `sent`, with the exact `dl_file` keys (1/2/3/space/h/m/escape→`session.abort()`) + `beep_percentage` between chunks (NO `wait()` — the write paces it); then `http_response@ resp = http_response(); session.receive_response(resp)`; branch on `int(resp.status)` (200→finished, 403→token, 413→toobig, else failed). Whole thing in `try{}catch{}` (network errors → "failed"), trailing `return "failed"` for the flow analyzer. NVGT strings are binary-safe so `.map` bytes survive `f.read`/`body.write`.
  **PROVEN WORKING end-to-end 2026-08-29** after three fixes found by iterating on compile/run errors: (1) the type is **`http_client`** not `http_client_session` (compile error); (2) mirror NVGT's own `http` class — set **`req.host = host`** and **`req.content_type = "application/octet-stream"`** (belt-and-suspenders); (3) **THE REAL FIX — the Python server MUST speak HTTP/1.1** (`protocol_version = "HTTP/1.1"` on the handler).
