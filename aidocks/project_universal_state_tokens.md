SimpleFighter has THREE token layers in the command pipeline, resolved at different points (14.8):

1. **`random(low,high)`** — universal, resolved by the string-to-number routine (`stn`) for any numeric field anywhere, plus `expand_random_tokens` for text contexts like `/speak`. See the random() paragraph in commands.txt / maps.txt.
2. **Universal state/position tokens** — `expand_state_tokens(cmd)` in `src/includes/main/functions/mapfuncts.nvgt` (right after `expand_random_tokens`). Called once in `comparse()` (`command_parser.nvgt`) right after `string command = sd[1];`, before the args split. 23 tokens: `%health% %maxhealth% %healthpc% %stam% %maxstam% %stampc% %level% %xp% %xpneeded% %xpleft% %points% %lives% %kills% %speed% %jump% %minx% %maxx% %miny% %maxy% %minz% %maxz% %x% %y% %z%`. **`%xpneeded%` / `%xpleft%` (14.9):** `%xp%` is the current CUMULATIVE experience (`xp`); `%xpneeded%` is the next-level total threshold (`xprequiered` — note the misspelled global name); `%xpleft%` is `xprequiered - xp` clamped to >=0 (the same remaining number the level-up combat-log line prints). Placed just before the `%xp%` line — `%xp%` is not a substring of either (the char after `xp` is `n`/`l`, not `%`), so no clobber. **`%minx%`…`%maxz%` (14.9)** report the current map's bound globals (`minx`/`maxx`/`miny`/`maxy`/`minz`/`maxz`, the same ones `/loc` reads), added just before the `%x%` line; safe against `%x%`/`%y%`/`%z%` since the min/max prefix keeps the axis letter from being flanked by `%`, so neither is a substring of the other. **`%speed%` (14.9) reports `modspeed`** — the LIVE effective movement speed used in the walktime formula (game.nvgt), NOT `player_own_speed` (the set preference the add/set/subspeed commands edit); the two match when no tile zone overrides speed, but inside a speed tile zone `%speed%` reflects the zone's value, consistent with the live-value semantics of the other tokens. **`%jump%` (14.9)** is the exact analog for jump height: reports `jumpheight` (live/zone-aware), not `player_own_jump` (the preference the add/set/subjump commands edit); same 1-20 range, normal 5. Percentages use `round(.../...*100, 2)` (2 decimals, matching the stats screen). `%lives%` maps to the `lifecard` global; `%stam%`/`%maxstam%` map to `stamina`/`maxstamina`. Fast-path returns early if the command has no `%`. Replacements are ordered longest-first so none clobbers another.
3. **Element-specific tokens** — resolved by the element BEFORE `comstack`: map_timer time tokens (`%seconds%` etc.) via `expand_time_tokens`; input tokens (`%answer%`/`%choice%`/`%index%`/`%attempt%`/`%attempts%`) via `expand_input_tokens`. These only fill in inside their own element's command.

**Also universal (14.9): `%flag:name%`** — the map-flag token, a PARAMETERIZED scan-and-replace (not a fixed string_replace like the layer-2 tokens), so it lives in `expand_flag_tokens` in `src/includes/main/globals/flags.nvgt`, called in `comparse` on the line right after `expand_state_tokens`. Reads the session-scoped flag store `dictionary map_flags` (set by setflag/addflag/subflag/clearflag, cleared on map load); an unset flag reads 0. Name rules mirror map variables (letter-led, letters/digits/underscores) and reuse `mv_is_letter`/`mv_is_name_char`. See [[project_flag_store_plan]].

**Also universal (14.9): `%item:name%`** — the inventory-count token, another parameterized scan-and-replace: `expand_item_tokens` in `src/includes/main/globals/inventory.nvgt`, called in `comparse` right after `expand_flag_tokens`. Reads the name from after `item:` up to the CLOSING `%` (so item names with spaces/underscores work), substitutes `inv.count(name)` (0 if none held). Built as the foundation of [[project_logic_condition_plan]] (§1) but is universal — usable in any command/text. NOTE for anything that tokenizes a string containing this token: it must be expanded BEFORE splitting on spaces (item names can contain spaces); the logic-condition Tier 2 validator neutralizes it to a number first for exactly this reason.

**Why comparse is the right choke point:** every command funnels through `comparse` (console directly; macros/switches/sensors/inputs/timer via `comstack` → `process_pending_commands` → `comparse` per step). Because a stack like `setx 50; speak %x%` is split and re-dispatched one step at a time, `%x%` in a later step reads the value AFTER an earlier step changed it — async-safe by construction, no special-casing. State tokens even work inside timer/input commands for free, since those are already expanded (their own tokens) before reaching comparse.

**To add a new universal state token:** add one `string_replace` line in `expand_state_tokens` (mind the longest-first ordering), then document it in the commands.txt token section and the maps.txt universal-token note. The commands.txt "Character and position tokens." section lists **one token per line** (`%token% - explanation.`) — add a new line, don't append to a paragraph, so it stays under the 1024-char dock limit ([[feedback_dock_line_length_1024]]). maps.txt does NOT enumerate each token (it defers to commands.txt), so commands.txt is the authoritative full list. See [[project_feature_ideas]] for the element-specific input-token design and [[project_map_timer_plan]] for the time tokens.
