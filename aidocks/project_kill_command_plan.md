Model the surface on the four name-or-coord commands the dev pointed at: /build, /unbuild, /spawn, /despawn (all take `<type>` = newest-of-type, or `<type> x y [z]` = the one at that spot; friendly name -> keyword via `normalize_buildtype`; dispatch to a per-type handler). ## Settled decisions (dev-confirmed 2026-09)

- **SCOPE = 17 killable types** (everything with a real health pool, plus the three healthless one-shot destroyables the dev explicitly wanted):
  - **Kombat (6, all have a death path):** `npc`, `security_camera` (keyword `security_camera`), `security_jet` (keyword `jet`), `container`, destroyable `projectile`, `ttsenemie` (tts enemy).
  - **Transport (3, health, destroyed = wrecked, no reward):** `aircraft`, `vehicle`, `bike`.
  - **Structural health-bearers (5, own health pool + destroy-at-0, ranged/spanning tiles):** `wall`, `platform`, `staircase`, `door`, `spike`.
  - **One-shot destroyable (3, NO health field — a single hit removes them via their `destroyable` flag):** `clock`, `calendar`, `sign`.
  - EXCLUDED and why: bombs/mines/time bombs are NOT player-destroyable — their `destroyable` bool CHECKS OTHER entities' flags to blow those tiles up in the blast (they're the destroyers, not destroyable). checkpoint/hazard/wind/slant only reference the PLAYER's health or a damage amount; slant is explicitly non-destroyable.
- **Syntax (replaces the old `kill entity id x y` NPC-only form):**
  - `/kill <type>` -> kills the NEWEST of that type (full death treatment + reward). `/kill <type> x y` (2d/topdown) or `x y z` (3d) -> the one at that spot. An NPC is now addressed by the single keyword `npc` (like `/despawn npc`); category/subtype targeting is dropped, coords still pin a specific one.
  - `/killall` (bare) -> kills EVERY killable entity of all 17 types on the map. `/killall <type>` -> all of one type (e.g. `killall sign`).
  - Keywords mirror `/despawn`; friendly names via `normalize_buildtype`; short forms stay `kn` (kill) and `kl` (killall).
- **Rewards = Option A (pays out, like a real kill).** Killing a reward-bearing type by command pays its reward exactly as a weapon kill: `npc` -> xp + kills++ + loot drop + bodyfall + kill/punch sound (today's `/kill` already does this); the four camera-style rewarders (`security_camera`, `jet`, `container`, destroyable `projectile`) -> their xp += xp*level*xpmod + "Defeated" combat-log line (NO kills/loot). The other 11 (tts enemy, transport, structural, sign/clock/calendar) have no reward and just play their death/destroy cue and vanish. NOTE: a bare `/killall` therefore dumps all rewards at once — accepted by the dev.

## Death-path map (Explore agent, 2026-09) + RESOLVED mechanics

Two patterns found across the 17 types:
- **13 loop-killed health types** — a per-frame loop already checks `health <= 0` and runs the WHOLE death sequence (cue + reward + tile/flag cleanup + rider eject). So `kill_<type>` just finds the target and sets its health field to 0; the loop does the rest next frame. Death-block sites: npc `npcloop()` npc.nvgt:1936 (handles lives/revive — force-kill needs care), camera `camloop()` security_camera.nvgt:106, jet `jetloop()` security_jet.nvgt:387 (calls `award_jet_kill(i)`), container `containerloop()` container.nvgt:395, tts `ttseneloop()` tts_enemie.nvgt:200 (bodyfall, NO reward), aircraft `plainloop()` aircraft.nvgt:327, vehicle `vehloop()` vehicle.nvgt:246 (restores flags+ejects), bike `bikeloop()` bike.nvgt:238 (ejects), wall `wallcheck()` wall.nvgt:95 (removes `platform_ids` tiles + debris), platform `platcheck()` platform.nvgt:186, staircase loop staircase.nvgt:46 (removes `platform_ids`), door `doorcheck()` door.nvgt:296, spike `spikeloop()` spike.nvgt:86. HEALTH FIELD NAMES VARY: npc `.health`, camera `.camhealth`, jet `.health`, container `.health`, tts `.ttsenehealth`, aircraft `.plainhealth`, vehicle `.vehhealth`, bike `.bikehealth`, wall `.wallhealth`, platform `.plathealth`, staircase `.stairshealth`, door `.doorhealth`, spike `.spikehealth`. Arrays: npc `npcs`, camera `sucams`, jet `jets`, container `containers`, tts `ttsenemies`, aircraft `aircrafts`, vehicle `vehicles`, bike `bikes`, wall `walls`, platform `platforms`, staircase `staircases`, door `doors`, spike `spikes`.
- **projectile** — array `projectiles` is COMPACTED (`remove_at`, not null-sentinel), health `.projhealth`. Death-zero is triggered INLINE at hit sites, NOT in projloop. Reusable helpers EXIST: `award_projectile_kill(uint i)` (projectile.nvgt:379) + `destroy_projectile(uint i)` (projectile.nvgt:67). So `kill_projectile` = find, `award_projectile_kill(i)` then `destroy_projectile(i)`.
- **3 healthless one-shot destroyables** — clock/calendar/sign have NO health, only a `destroyable` bool; destroyed INLINE at every weapon/bullet/projectile hit site with NO shared helper. The identical inline sequence: `<pool>.destroy_sound(<entity>.<x>sound)`, play `*break*` into `hurtsound`, `update_sound_range_3d` to its span, `@<array>[i]=null`. Arrays `signs`/`clocks`/`calendars`, pools `signpool`/`clockpool`/`calpool`. So `kill_<type>` needs a NEW extracted `destroy_sign`/`destroy_clock`/`destroy_calendar` (or inline replica).

RESOLVED (no dev question needed):
- Riding transport: reuse the loop death path — it EJECTS the rider + restores capability flags (vehicle vehloop:246, bike bikeloop:238). Good as-is.
- npc: keep today's force-kill-with-reward (today's `/kill` handler already force-kills bypassing lives) — `kill_npc` must fully kill regardless of lives, awarding xp+kills+loot+bodyfall.
- **GATING = gate BOTH like `/despawn`** (dev-confirmed 2026-09): `(!map_is_compiled || trusted)` — on a compiled map they run only when a builder element (switch/sensor/input/map_timer) fires them; console/macro on a shipped map does nothing. (This CHANGES current behavior, which was ungated.)

## Reference model
`despawn_entity(type, by_coord, gx, gy, gz)` dispatch in `src/includes/main/parsers/map_parser.nvgt` (~line 195+) is the exact template — a big `if(type=="...") return despawn_<x>(...)` table returning bool (found+acted). The new `kill_entity(...)` mirrors it but runs each type's DEATH path (reward + death cue) instead of silent removal. Command handler pattern = the `/despawn` block in `command_parser.nvgt` (~743): `parsed.length()` gates bare-name vs coord form per mapmode. Current `/kill`+`/killall` live in command_parser.nvgt ~212 (kn/kill) and ~264 (kl/killall). See [[project_stability_rules]] (sentinel-null removal, per-z structural tiles, ranged min-corner match), [[feedback_alphabetize_commands]] (commands.txt + allcommands slot).
